## 有规程与空检索对照

在两个隔离 schema 运行相同的振动告警夹具，分别发布可访问的规程或留空。模型仅能从实际工具返回中得知检索结果。

| v3.14 模型 | 有规程 | 空检索 |
| --- | --- | --- |
| gpt-6.1-sol | 请求 1 首轮 HTTP 502 | 请求 2 首轮 HTTP 502 |
| gpt-6.2-sol | 请求 5–6 生成 Pending，关联工单 0。未查到已发布规程。 | 请求 9–10 生成 Pending，关联工单 0。未执行检索，无法据此确认空结果。 |

两份成功回答首轮都只选了测量。两案的第二轮记录均显示剩余 24,971 输入额度，提供工具需预留 21,353，高于剩余额度的一半，收回工具后为最终作答预留 19,939。这个记录解释了第二轮无法再检索；首轮模型选择测量的理由未知。结构通过与生成提案均不能代替规程语义验收。

## 取证提示实验与预算复核

隔离构建曾用候选提示提醒模型在尚有工具时合并独立读取。候选版本与 v3.14 使用相同工具、输入及输出上限、轮数和审批契约。候选版的空检索用例（请求 12–13）仍只读取测量。有规程用例（11、14）及限制为单轮的直接作答对照（15）均收到 HTTP 502，后两项语义不可评。实验结束后保留 v3.14，生产提示、分支和运行成本均无新增。

冻结请求还可用于检查下一步设计是否可行。以请求 6 为例，最终请求正文为 19,683 字节，其中输出结构字段占 7,184 字节。就算假定在被撤回的同上下文工具帧里移除这整个字段及分隔符，21,353 的预留也仅降到约 14,168，仍高于当轮一半额度 12,485。后续设计应同时考虑取证帧大小、证据投影以及下一帧的作答预留，并保留证据已足时直接作答的路径。这个离线计算未调用模型，也不能证明一种新编排会改善检索。

本轮账本结算为 **15 / 100 次真实请求**，9 次收到模型返回（含工具选择），6 次 HTTP 502。10 次调查中有 4 份最终回答；其中 1 份稳定工况回答经核对并走到 Closed，3 份规程夹具回答均未执行文档检索。其余 6 次调查没有可评最终回答。失败请求的供应方用量未知。所有已发送请求与保存的请求体摘要一致；剩余 85 次保留在原账本。独立配对评审样本为 0。
