## 实现边界与配置

单 Worker、最多 200 个活跃源，所有源队列预算合计不超过 10,000 个样本；单源最多 200 点，每批最多 500 条。有限 Simulation 枚举按一秒周期再次采集；持续流无需结束枚举即可提交。载荷与事件键有上限，满队列丢弃最旧样本并登记损失。入库有限重试，非法点位隔离，关闭源时限时排空。

损失摘要在内存中聚合，不是持久离线队列。数据库恢复后按稳定 ID/绝对数量重试；进程崩溃可能丢失未保存摘要。启动根据最后观测打开确定 ID 的 `PossibleCrashTail`，数量未知、`IsPossible=true`，恢复后关闭；不伪造停机读数。显式缺口中断待触发/待恢复计时，不擅自清除 Active 告警。晚到的缺口也能覆盖已保存、未 dirty 的分钟查询结果。

Outbox 清理默认关闭，保留本机既有验收历史。显式设置 `Outbox__RetentionEnabled=true` 后，仅清理 `DispatchedAt` 严格早于截止时间的已发送记录；默认 `SentRetentionHours=24`、`CleanupBatchSize=1000`、`CleanupIntervalSeconds=5`。未发送、重试和审计不清理；采用事务与 SKIP LOCKED，失败回滚。默认理论清理吞吐 200 行/秒，实际吞吐和期限选择仍需容量实验。

新增 `20261006002351_ReviewIngestionAndOutboxSafety` 迁移，只扩展缺口字段及已发送通知索引。正常启动仍不自动迁移。新代码需要该迁移；部署前按 README 停服务、备份并显式迁移。本轮只迁移隔离测试 schema，**业务库 `plantops` 和原验收 schema 未升级，既有卷、文件和资料未清理**。
