# P1.3 Telemetry Implementation Plan

**Goal:** North Plant → Utilities → P-101 的 VIBRATION_RMS 从可重复 Simulation Source 写入 PostgreSQL，在授权页面查看质量、新鲜度和历史趋势。

**Architecture:** Domain 保存点位、来源、映射、不可变读数和最新投影；Application 定义 IMeasurementSource、标准样本、读取/入库契约及质量规则；Infrastructure 实现模拟适配、EF 事务、授权查询；Worker 运行单实例采集；API 不开放测量写入。

**Tech Stack:** 现有 .NET 10 / EF Core / Npgsql / PostgreSQL 17 / Vue / SVG，继续使用锁文件与 OpenAPI 类型生成。

1. 检查 P1.2 衔接与基线：独立数据库回归，确认环境、文档和工作区；不修改业务库、不覆盖本地凭据。
2. 模型与采集：MeasurementPoint、DataSource、SourceMapping、MeasurementReading、PointLatestState；数据库同厂复合外键及一个启用映射的部分唯一索引；固定 ID 种子保留人工修改。标准样本带来源/映射版本、事件键、源/服务器/接收时间；模拟场景按 UTC 秒确定，1 Hz，包含正常/升高/Bad/Uncertain/恢复。
3. 事务入库与质量：每批最多 500，去重、有限数值、单位转换、时间异常、陈旧、乱序、LastGood 独立保留；工厂写锁与目录变更协同，归档停用点位/映射并保留历史。Worker 每批等待落库并有限重试，不引入无限队列或自动回退。
4. 授权 API：点位定义/最新观测/历史可信值；强制资产与点位范围、UTC 时间窗口、原始最多 24h/10000 行；按需分钟聚合最多 1440 桶，质量/缺口可见。提供 Admin 的点位、Simulation 来源/映射配置用例，version、防伪与审计沿用 P1.2；已存在读数后禁止改点位单位/数量类型，启用映射禁止原地换来源。
5. Vue：设备测量面板、单位/来源/时间/新鲜度、历史窗口与 SVG 断线曲线、失败与空态；Admin 定义配置入口。生成 API 类型，类型/构建检查并实际浏览器验收。
6. 独立 PostgreSQL 测试：去重、乱序、Bad/Uncertain/NaN/未来时间/时间回退、事务回滚、授权隔离、查询边界、配置并发/审计、归档与重复初始化；实际 Worker 入库与停止后陈旧。更新 README/ROADMAP/设计及验收记录。

每个完成并验证的实现阶段立即提交；不推送、不创建 PR。不实现告警、工单、OPC UA、AI、SignalR、分区或保留清理。分钟聚合在本阶段按需计算，持久化投影留到 P1.7。历史查询受行数上限保护，不宣称规模性能达标。
