# P1.2 Implementation Plan

**Goal:** 登录后按角色与工厂范围浏览、管理 North Plant → Utilities → Cooling Pump P-101。

**Architecture:** Domain 保持纯实体；Application 定义 actor、目录 DTO 与用例端口；Infrastructure 实现 Identity、范围查询、业务事务和审计；Api 提供同源 Cookie、防伪与授权入口。Vue 使用真实 API，显示错误与版本冲突。

**Tech Stack:** .NET 10 / Identity / EF Core 10 / PostgreSQL 17 / Vue 3 / TypeScript。

1. 复盘并修复 P1.1：环境保护、README 凭据保留；锁定恢复、模型检查、独立数据库测试、真实在线/离线健康验证。验证后提交。
2. 后端：Identity 迁移、四角色与 UserPlantAccess；本地密码配置的双厂种子；目录读取/创建/编辑/归档、范围与关系校验、version 409、同事务 AuditLog。工厂内写事务加锁，避免并发树修改产生循环；不物理删除历史。用真实 PostgreSQL HTTP 集成测试验证后提交。
3. 前端：登录/退出、工厂与位置导航、设备详情及 Admin 管理表单；403/404/409/网络失败可见。类型检查、构建及实际浏览器登录→浏览→编辑验证后提交。
4. 更新 README、ROADMAP、架构/领域文档与验证记录，完整回归后提交；不推送、不创建 PR。

测试连接强制使用名为 plantops_tests 的独立数据库；不清空业务库。演示密码通过本地配置提供，缺失时拒绝账号初始化；重复初始化不重置密码、角色、授权或资产修改。
