# Docker Implementation Plan

**Goal:** 用 Docker Compose 启动完整本地演示，无需宿主机安装 .NET 或 Node。

**Architecture:** 根目录 `compose.yaml` 提供独立的 `plantops-demo` 项目；保留 `deploy/compose.yaml` 的数据库开发环境。Nginx 托管前端并代理 API/WebSocket，API 和 Worker 共用文档卷，数据库与 API 登录密钥分别持久化。初始化由明确的一次性命令执行，普通服务启动不自动迁移。

**Tech Stack:** .NET 10 SDK/ASP.NET runtime、Node 22、Nginx、PostgreSQL 17、Docker Compose。

## 方案选择

1. 推荐完整 Compose 演示栈：统一访问入口、独立数据库与卷、启动脚本负责显式初始化。
2. 只增加后端镜像：仍需宿主机前端环境，不能完整满足容器启动。
3. 修改现有数据库 Compose：可能影响正在使用的本地业务库与端口，保留原文件更合适。

## 实施步骤

1. 增加根目录 `.dockerignore`，排除 Git、构建结果、本地配置、凭据、备份和上传文件；镜像仅复制必需源码与锁文件。
2. 增加 `deploy/Dockerfile.backend` 多阶段构建，通过 `api` / `worker` target 生成非 root 运行镜像，内置健康探针并准备文档和密钥目录。
3. 增加 `deploy/Dockerfile.web` 和 `deploy/nginx.conf`，构建前端，代理 `/api/`、`/hubs/`、`/health/`、`/openapi/`，保留 Host、WebSocket、长请求及上传限制。
4. 增加根目录 `compose.yaml`、`deploy/docker.env.example`、`deploy/Start-Docker.ps1`。凭据仅在运行时注入；真实 AI 默认为 Fake。初始化失败则终止，不启动不完整业务服务。
5. 新增 `docs/DOCKER.md`，更新首页、开发指南和文档导航，说明启动、重建、数据持久化、可选 AI 和本地 Development 限制。
6. 验证 Compose 解析、镜像构建、独立演示环境初始化、健康、登录、防伪、静态路由、Worker 入库、文档读写、SignalR 和重建后的持久化。测试仅使用新的 Compose 项目，不修改已有开发数据库。

## 验收约束

- 默认仅发布 `127.0.0.1:8080`，数据库/API/Worker 不发布宿主端口。
- Development 初始化及 HTTP Cookie 行为仅用于本地演示，生产部署需单独配置 HTTPS 和迁移流程。
- 保留已有 README 整理改动，不提交本地凭据，不调用付费模型。
- 记录实际验证结果；网络或基础镜像不可用时如实记录未完成的容器验证。
