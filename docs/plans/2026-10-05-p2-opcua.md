**Goal:** 在保留 Simulation Source 与人工业务闭环的前提下，新增可追溯、只读、受权限和容量约束的 OPC UA 数值订阅，并通过故障与负载验收。

1. 记录 Docker PostgreSQL 卷实际路径、Docker 虚拟磁盘/宿主文件系统余量及上限，区分 D 盘与容器 `df`；测量 heap/index/TOAST、Outbox、分钟、gap/审计、WAL、文件、备份和共享历史。不得删除当前 schema 或移动/重建数据库卷解决容量。
2. 制定 Outbox 策略：计划默认已发送保留 24h（新建议，待实现时同步配置文档）；仅 `DispatchedAt != null && DispatchedAt < cutoff` 可清理。未发送/失败/领取中均保留，业务事件历史在业务表/审计，不拿 Outbox 代替审计。分批上限、索引、事务竞争、重复运行幂等及失败回滚先测试；失败行积压触发告警，不静默删。
3. 预算使用 `峰值原始+分钟+Outbox+gap/审计+文档+WAL峰值+备份/恢复峰值+现存数据`，再加不低于 30% 余量（本计划开发门槛，非生产容量承诺）。原始按整日清理，稳态可能保留接近八天：100×1 Hz×8天=69,120,000 行；不能只预算精确七天。采用 P1 行宽时八天 raw 约 40.6 GiB；Outbox 24h 粗估约 1.6 GiB，均须重新测量。
4. 在容量充足、独立且保留的 `plantops_tests` schema 填充 **60,480,000** 七天完整 raw 行，覆盖真实值/状态/索引/分区；另验证第八天边界/过期日滚动。可加速生成，但记录生成模式，不把它称为七天持续运行。保留现有 P1/P2 试验数据与文件，预先把所有已存测试历史计入预算。
5. 记录各分区实际行数/大小；聚合、保留与 100 Hz 实时写入/五客户端同跑，记录锁等待和队列峰值。分钟 90 天数据与空间、Outbox 清理稳态、冷/热查询、备份和恢复均在专用验收空间核实。联合数据库/文件备份恢复到新增测试 schema/目录，不覆盖演示。
6. 引入容量警告与限流边界：建议可用余量低于预算安全余量时 Degraded，低于已测一次维护/WAL峰值时停止新采集并登记 gap；阈值以实测字节配置，不能仅看宿主百分比。恢复需重检，不删未聚合原始数据。业务读取保持可用，数据库本身不可用仍 ready=503。

**通过条件：**容量表含真实卷余量、八天边界预算、WAL/备份峰值和 30% 余量；七天满量+第八天滚动验证通过；每日过期 raw 删除前 dirty=0、Revision一致、raw/aggregate样本数一致；原始/告警/工单快照保留；Outbox pending 不被删且已发送历史不无界增长；列表/概览热 p95<500ms、UI p95<2s 在维护并行期间成立。任一无证据，G0 保持未通过，禁止满量持续接入。

## P2.2：配置、映射与标准化

**修改：**`src/PlantOps.Application/Telemetry/TelemetryContracts.cs`、`SamplePolicy.cs`、`TrendBuilder.cs`；`src/PlantOps.Domain/Telemetry/TelemetryEntities.cs`；`src/PlantOps.Infrastructure/Telemetry/TelemetryService.cs`、`MeasurementIngestor.cs`、`MeasurementMaintenance.cs`；`Persistence/TelemetryModel.cs` 与新迁移；`src/PlantOps.Api/TelemetryEndpoints.cs`；`web/src/components/TelemetryConfiguration.vue`、`MeasurementPanel.vue`、`web/src/generated/api.d.ts`。**新增：**`src/PlantOps.Integrations.OpcUa/` 配置解析/标准化代码、项目文件及 solution 引用。**测试：**`OpcUaMappingTests.cs`、`OpcUaNormalizationTests.cs`、现有 `TelemetryTests.cs` / `MeasurementMaintenanceTests.cs`。

1. 扩展来源类型 schema：DataSource 保存经校验的 endpoint引用、安全策略/模式、连接限额与 `CredentialRef`；SourceMapping 保存版本化 NamespaceUri、IdentifierType、Identifier、采样/队列请求和读取模式。分离请求 DTO、内部秘密配置与只读 DTO，凭据/私钥/存储路径不返回或写 AuditLog。Kind 建立后不可通过 PATCH 直接改型；Simulation 配置保持兼容。
2. 身份固定为 **URI + IdentifierType + Identifier**，每新 Session 查 NamespaceArray 再解析，不保存 `ns=2` 为稳定身份。支持类型先限定 Numeric/String/Guid 标识符；Opaque 若未完成字节规范化测试就明确拒绝。节点显示名不是匹配键。校验 Variable/Value、标量 ValueRank、访问权限/类型/单位；缺节点只禁用该映射并给具体错误，不把值补 0。
3. 只开放经批准 endpoint 与 Namespace/节点范围内的分页 Browse（默认50/最大200、总量/超时限制、continuation正确释放）。批准列表由受控部署配置提供，应用 Admin 不可用任意 URL 扩大列表；校验服务端返回的 discovery endpoint、主机/端口与地址解析，防止经重定向绕过允许列表。API Host 不读取工业凭据，命令交由 Worker 执行并返回有时限的授权结果。
4. 数值支持表：Byte/SByte/Int16/UInt16/Int32/UInt32/Float/Double 标量，经范围/有限数值检查转换。Int64/UInt64 超出 double 精确整数范围拒绝或 Bad/null；Boolean/String/数组/结构不隐式转数值。保留原始类型及有长度上限的原值，统一 `raw×scale+offset`。支持 mm/s↔m/s、degC↔K 等显式量纲白名单，未知/冲突单位禁止启用，换算溢出 Bad/null。
5. 保留完整 StatusCode 和符号，质量分级与信息位独立；无效时间（SDK 零/最小值等）先转缺失。EffectiveAt=有效Source→有效Server→Received，记录 Origin，源时间未来>5s标异常、过旧标迟到；不倒灌最新可信或在线告警。未来极端日期设可配置异常隔离范围，避免任意建远未来分区；拒收登记原因，历史保真与隔离存储策略在 spike 中确认。
6. 源事件键规范化 `(mappingId,version,可信sourceAt或serverAt,原始类型/值,完整status)` 后哈希；有源时间不加入可变化 server时间。缺可信时间使用 Envelope ID，入库重试复用；新同值通知仍是新观测。SDK序号仅诊断，不代替跨重连去重键。相同Envelope重试跨UTC边界仍保留原EffectiveAt。
7. **关闭 R4：**保存带生效时刻的采样语义/订阅修正参数快照（计划新增 `SamplingProfile` 契约，最终表设计随迁移评审）。周期模式按当时实际 interval/生效区间计算覆盖；变化模式返回覆盖率未知及模式标记，不以低数量宣称丢物理采样；同分钟切换按各区间计算。旧历史无法证明间隔时标未知，不改原始观测。Good+Overflow 不作为连续可信输入，保留原码并另发 gap信号。
8. 同一点位唯一启用映射保持数据库部分唯一索引。停用旧版本→取消/隔离旧回调与队列→确认消费屏障→更新/启用新版本→重建订阅；旧样本被版本检查拒绝需登记配置切换损失，不让一个错误样本长期阻断全源。已采样单位/量纲保护、同厂关系、事务审计、防伪与 version 不退化。

**通过条件：**矩阵 M01–M08、M17–M20 通过；已有 P1 非空 schema 升级后行数/工单/文档/单位不变、EF 无 pending；DTO/Domain 无 SDK 类型或秘密；一个点先安全入库，再扩展。SDK接口实现以 G1 的签名为准，本计划不虚构未经验证的代码。

## P2.3：只读 Session/Subscription 与有界队列

**新增：**`src/PlantOps.Integrations.OpcUa/OpcUaSource.cs`、`OpcUaSessionClient.cs`、`OpcUaSourceRuntime.cs`、可追踪丢弃的缓冲实现；Application 新增健康/连续性端口。**修改：**`src/PlantOps.Worker/MeasurementWorker.cs`、`Program.cs`、Host配置/注册，Infrastructure注入与共享入库。**测试：**`MeasurementPipelineTests.cs`、`OpcUaLifecycleTests.cs`、`OpcUaReadOnlyTests.cs`；模拟器验收脚本。

1. 首先写 Fake Source 回归：不结束的低速流、多个源、热改配置、取消与异常；证明当前批次循环失败，再建立每源单活跃执行者+统一消费端。`SimulationEnabled=false` 只停模拟执行者，不退出全部采集；保留单 Worker，设置源/点总量上限。
2. Session 仅允许 Find/GetEndpoints、Browse、Read、Subscription/MonitoredItem及必要诊断/恢复服务；**业务 Adapter 不暴露 Write/Call/HistoryRead**。用服务调用记录器检查实际服务，并用 Server 只读账号验证权限。SDK可用 API多不代表业务可以调用。
3. 首个连接即执行证书/主机/ApplicationUri/策略校验，默认 SignAndEncrypt+显式锁定策略，无 None降级、无 AutoAccept。建立 Session→读 NamespaceArray→逐项校验→创建 Subscription/Value Reporting MonitoredItem。部分节点失败只标其映射，源健康 Degraded。
4. 初始请求 publishing/sampling=1000ms、MonitoredItem queue=10/discardOldest；记录服务器 revised值、keep-alive/lifetime。周期验收使用已验证 StatusValueTimestamp；变化模式静默不等于断线，健康 Read 频率有上限并标模式，不假装额外物理样本。
5. 回调捕获不可变 Envelope（映射版本、原始值/码/时间、received、事件键）并快速入队，不查询SQL/模型。每源缓冲初始上限10,000条，总源数/总字节也有上限；通知 payload上限防止10,000个大对象突破内存预算。
6. 容量满 DropOldest，必须获取被丢Envelope，累计point/time/count/reason；不能使用静默DropOldest。消费者每500ms或500条先到即写，同点有序，迟到只归档；多源公平轮转避免一个坏源阻断模拟源。入库事务失败有界3次重试并保持Envelope ID；校验错误隔离后提交有效批次，隔离损失登记gap。
7. 优雅停止取消回调/会话、有限时间排空；超时记录可能损失。记录队列水位、批次耗时、重试/丢弃、提交水位；源码没有 Worker→Hub连接，沿现有 Outbox推送。

**通过条件：**1点低速流500ms触发flush，500条立即flush；100Hz持续入库，重复通知插入/告警重复=0；配置撤销后不再以旧版本提交；模拟与OPC UA不同点并存、停模拟不影响OPC；所有只读审计通过。100点30分钟试验预算先经G0。

2. 不可信/过期/尚未生效/hostname或ApplicationUri不匹配拒绝；策略不匹配Faulted。None只在显式Development且本机/隔离允许列表可用，UI警示，非Development启动/启用拒绝。服务器用户凭据通过CredentialRef仅Worker解析，SDK异常不得泄漏密码/令牌。
3. 状态：Disabled→Connecting→Connected→Degraded/Reconnecting→Connected；安全/配置错误Faulted。单源最多一个重连任务，退避1/2/4/8秒至30秒±20% jitter；停止/改版本取消旧任务。KeepAlive判断用修正参数，连接健康与LastGood新鲜度分开。
4. 优先SDK恢复Session/订阅，在支持且序号可用时Republish/Transfer；失败或不支持则重建。每新Session重读NamespaceArray，以URI解析；URI消失不能沿用旧index。恢复受限Read当前快照，标RecoverySnapshot；不是历史补采。不支持功能为确定分支，不能无限重试。
5. gap持久契约：point/source、From/To、reason、DetectedAt/RecoveredAt、knownDroppedCount?、uncertainty、幂等episode key。涵盖Disconnect、ServerOverflow、QueueOverflow、DatabaseUnavailable、ConfigurationChanged、ShutdownTimeout、PossibleCrashTail。无通知但连接存活与真正离线分开，不为恒值变化模式制造损失数量。
6. 故障时立即打开gap并重置受影响点pending（保留Active）；恢复后关闭区间，不能等下条样本才宣称故障发生。数据库离线存有界摘要；恢复幂等写gap。进程重启由last committed水位到恢复时刻记可能尾部，未先落盘的精确丢弃数量不承诺可恢复。摘要持久化如有本地日志文件须限额/保留策略，不做无限离线队列。
7. 显式gap加入趋势和分钟的质量标记，即使剩余样本数量足够或时间差很小也断线；Good+Overflow保留原Quality/Status但连续性失效，不用于触发/恢复持续计时。正确排空/重传可证明已补齐的区间才缩小gap，不凭连接恢复删除未知区间。新增gap不能绕过原始保留/聚合安全核对。

**通过条件：**M09–M16、M21通过；未授权批准/撤销均拒绝；故障未恢复也能查询开放gap；数据库恢复/重启不重复gap和告警；恢复后必须重新取得连续可信样本才能恢复Active。无HistoryRead、无模拟值自动回退。
