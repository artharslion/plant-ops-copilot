# P1.4 Alarm Implementation Plan

**Goal:** P-101 振动持续升高只产生一个活动告警，授权用户可确认，可信低值按回差和持续时间恢复；质量不可信时保持既有告警。

**Architecture:** Domain 增加 AlarmRule/RuleRuntimeState/Alarm/AlarmEvent；Application 提供纯阈值状态机与查询/配置/确认契约。Infrastructure 在现有测量事务和工厂锁内评估新读数、写运行状态/事件/审计，API 强制角色与范围；Worker 首次成功采集前清零待判计时。Vue 告警台使用 HTTP 轮询。

**Tech Stack:** 现有 .NET 10、EF Core/Npgsql、PostgreSQL、Vue 和生成的 OpenAPI 类型，无新增依赖。

1. 复核前阶段、版本/工作区/仓库约定与规格；独立 plantops_tests 数据库基线回归。
2. 模型、同厂复合外键、每规则唯一 Active 部分索引、不可变事件、持久规则水位；先用纯状态机测试覆盖边界/持续/回差/无效质量/迟到/缺口/重启，生成迁移。
3. 新读数按本批顺序在线评估，去重不重演，读数/最新值/规则状态/告警/事件/审计同事务；来源或配置版本变化清零计时；Worker 启动清零计时，Active 保留。
4. 受授权 API：厂内告警游标列表、按 ID 详情和事件；Operator/MaintenanceEngineer/Admin 确认、Viewer 只读；确认幂等，首次要求 version，已确认重复不覆盖人/时间。Admin 点位规则创建/编辑/停用，有 Active 时禁止修改；演示种子 10/8 mm/s、3/5 秒、MaxGap=2500ms。归档设备有 Active 时拒绝，防止失去恢复来源，已恢复历史保留。
5. Vue 告警台：工厂/Active 与历史筛选、详情/事件/阈值快照/数据可信状态、授权确认和 Admin 规则配置；设备页链接对应工厂/设备告警。界面不把确认表达为恢复；刷新失败清空未验证状态。
6. 真 PostgreSQL 验证去重/并发唯一、质量/迟到/未来、跨厂查询与写越权、防伪、确认角色/幂等/并发/审计回滚、规则配置/种子/来源切换与重启；前端 npm ci/类型/构建与真实 Worker→告警→确认→恢复 UI。更新 README/ROADMAP/设计和验收记录。

每个完成并验证阶段立即提交，不推送/不创建 PR。测试与 UI 均仅 plantops_tests，UI 使用新 schema，不迁移业务库。枚举 Severity 采用 Low/Medium/High，固定 HighThreshold；限制每点位 20 条规则，持续时间 0–300000ms、间隔范围从期望间隔到 300000ms。列表默认 50/最大 200，按 StartedAt/Id 游标；规则运行版本与来源 ID/version 用于隔离旧计时。不实现人工强制恢复、告警删除、工单、OPC UA、AI、Outbox 或 SignalR。
