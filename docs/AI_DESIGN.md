# AI Copilot 设计

本文概述当前调查链路和稳定边界。新调查的字段、状态、校验及工单就绪判断以 [调查建议 v3](INVESTIGATION_RESPONSE_V3.md) 为准；任务状态见 [开发计划](../ROADMAP.md#4-p6ai-多源联合调查增强)。无需为普通调查改动读取旧版设计。

## 执行与证据

用户从告警手动创建 AiRun，Worker 执行单 Agent 调查，通过既有 `ILlmGateway` 调用配置的 Provider。采集、规则计算和实时页面更新不触发模型。生产入口为 `InvestigationEngine`；`LegacyInvestigationEngine` 只供历史回放和兼容。

初始上下文包含所选告警、设备摘要及强制当前点位/质量证据，详细测量、相关告警、维护和授权资料由受控只读工具按需读取。查询范围、时间截止、参数、大小与次数有界，重复读取复用冻结证据；完整证据与 hash 保留，模型投影可按预算裁剪并披露省略。

Source/Server/Receive 时间、事件/恢复/当前窗口、质量、连接健康和测点配置版本分别保留。无通知、值不变和 KeepAlive 不单独证明当前观测有效或传感器故障。具体窗口与引用语义见 [证据与工单质量](AI_INVESTIGATION_QUALITY.md)。

## 建议与人工工单

调查执行状态、AI 建议可用状态、结构化发现及工单就绪状态独立，不通过解析说明文字推导状态。服务端校验结构、授权引用、对象、交叉链接及权威当前点位事实；原因推断、规程适用性和建议语义仍需质量评审。结构通过不等于物理诊断正确。

建议包含可核查任务、记录、完成条件和升级责任；工单草稿复用同一建议任务，不另调用模型。对象、优先级、指派、版本、过期、权限、事务和幂等由服务端控制，最终执行依赖人工核查与明确确认。旧 v1/v2 结果保留原格式及展示路径。

## 确定性系统与 Agent 的职责边界

AI 调查是通用的、受限的证据推理流程，不是按设备故障、告警类型或自然语言关键词排列的场景分支。确定性代码负责来源/时间/质量计算、权限、授权工具、证据引用、v3 类型化状态、版本、事务与人工审批；LLM 负责在授权证据内选择补充读取、解释现象、提出可验证假设和核查建议。结构化输出通过并不证明诊断正确。

不得为了让个别真实模型样本通过，就将“升温、恢复、安全、可能”等词语匹配或固定描述格式写进当前 `InvestigationEngine` 的语义判定。发现问题先归类为证据、编排、契约或语义质量缺陷；确有权威不变量时修通用校验，属于推理与建议质量时改进证据/Prompt 原则与独立语义评估。合法的确定性规则、协议处理、只读工具和业务安全边界必须保留。

实施和评审详细规则见 [AI 工程约束](AI_ENGINEERING_GUARDRAILS.md)；验证应同时考虑错误接受和错误拒绝，避免新测试案例不断推动特殊规则增长。

## 权限、预算与诊断

工具按 actor/工厂/资产范围授权；文档发布、版本、ACL 和 hash 在读取、展开与工单确认时重查。模型、上传资料和工具返回的文字不能扩大权限或新增写操作。

实际模型、输入/输出预算、轮数、工具数和超时取当前配置与运行快照；请求发送前校验预算。报告用量与未知预留分开，失败保留，不自动重试或提高预算。关联诊断、原始回答捕获及留存边界见 [调查诊断](INVESTIGATION_DIAGNOSTICS.md)，本机凭据不写入仓库。
