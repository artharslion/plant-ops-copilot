## 本轮交付

沿用告警点及按编号排序的最多两个同设备启用候选，不推定物理关联。短暂 Repeatable Read 事务冻结当前告警、目录、读数、配置、来源健康、采样配置和启用规则；事务在工具/模型执行前结束。当前观测的有效时间和接收时间均不得晚于 asOf。

`PointStatus` 证据保存结构化快照及可展开事实：点位/读数 ID、单位、质量、原始状态码、有效/源/服务器/接收时间、时间来源、来源/映射/测点版本、来源健康及更新时间、采样模式、启用规则 ID/版本/阈值、窗口质量与缺口。证据 hash 包含结构化内容，继续受原调查的拥有者、工厂授权和资料撤回规则约束。

此前原始读数没有来源版本和测点版本，不能用当前规则状态猜测。因此新增 nullable `MeasurementReadings.SourceVersion/PointVersion`，入库时从已经核验的 SourceConfiguration 保存。不回填旧读数；未知版本不能被当前配置追认。更换来源、测点或映射版本后，旧样本不能支持当前可信判断，新配置下的新样本重新提供依据。

API 增加可选 `assessment`，从持久化的逐点状态汇总，不由模型生成，不在查看旧调查时用当前设备状态重算。旧调查没有 PointStatus 时为 null，不补写标签。

## 确定性判断规则

| 固定反例 | 当前数据可信度 | 当前设备异常证据 |
|---|---|---|
| 温度 Bad，振动可信且超阈值 | 部分可信 | 存在，保留振动依据 |
| 所有当前点失效，历史告警仍 Active | 不可验证 | 证据不足 |
| 已检查点全部可信且有适用规则，均低于恢复界限，无遗漏启用点 | 可信 | 未发现，仅限本次范围 |
| Changes 点静默且观测陈旧，另一点可信 | 部分可信 | 按有效点判断；静默不证明传感器故障 |
| 无适用规则、回差区间、规则截断或未检查点位 | 按已得观测给出 | 无其他可信超限时为证据不足 |

当前可信要求 Good/有限值、最新可信投影、无时间异常/溢出、未陈旧、有观测时间而非仅接收回退、来源/测点/映射版本相符、配置启用。OPC UA 另需当前版本且未超过十秒的 Connected 健康记录和有效采样配置。KeepAlive、来源级接收时间不替代逐测点新鲜度；仿真标识继续保留。

“存在”只表示可信当前读数超过某个启用高阈值，不确认持续超限、根因或安全，不修改告警状态机。“未发现”要求所有已检查点具备适用规则并满足下界比较，且无遗漏启用点。每点最多读取二十条启用规则，超限截断不得给全范围未发现。

事件、恢复、当前完成分钟窗口分别保存 UTC 范围、实际查询时间、Good/Bad/Uncertain 数、缺口和原因。现有分钟投影不保存逐样本来源版本，所以有 Good 的历史窗口也只标部分可信，无 Good 为不可验证；覆盖率不证明完整身份或物理采样。窗口查询可能晚于 asOf，查询时间单列，不声称快照包含“截至 asOf 已入库”的完整历史。历史窗口限制不抹掉另一个窗口或当前可信读数。

## 模型、页面与工单

Prompt 为 `investigation-extractive-v9`，沿用 InvestigationResult.v1；可信策略为 `point-current-window-trust-v1`。模型收到服务端标签与逐点事实，不能生成结构化标签；保留原事实/引用校验，对明确改写标签、宣称已确认设备安全的输出判失败。已捕获服务端证据不因模型失败而伪装成成功答案。

PointStatus/Assessment 属于状态与范围元数据，不能单独作为故障原因假设的 basis；假设仍须引用既有观测事实。质量不可信本身不能被包装成传感器或设备故障原因。

页面展示两维标签、取证时刻、检查范围、逐点状态/原因/时间/来源、历史窗口和引用，明确提示取证快照不代表页面此刻状态。旧调查保持原展示。工单草稿引用同一账本的两维摘要和逐点状态；提案不执行业务工单，继续人工确认、权限/版本复核、幂等执行，旧调查/提案 hash 不重写。
