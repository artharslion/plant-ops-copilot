# 人工排查与 AI 辅助排查对照记录

每例使用一个编号。独立评审者先准备案例，工程师按 A、B 顺序分别保存两份记录，最后由评审者填写 C。复用已公开案例可用于演练，独立留出集另行统计。

## 评审者准备

选择至少一例关键证据充分、一例关键证据不足的未见案例。保留同一设备在同一截止时刻的可见资料，记录单位、质量、告警与恢复、采集缺口、可访问的工单及规程版本。标明每项资料的标识，以及查询无结果、无权限或数据实际缺失的区别。排查者与 AI 使用相同权限、时间窗口与资料版本；另记 AI 实际选择和收到的内容。

把以下信息另存为评审底稿，只向排查者提供案例编号与可见资料。在首答前固定底稿版本和时间，不把底稿放入 AI 可检索资料。

| 案例编号及数据截止时刻 | 未参与调优的来源说明 | 关键证据标识及其意义 | 仍无法判断的问题 | 可区分的两种解释、预期检查及可接受的等价检查 |
| --- | --- | --- | --- | --- |
| | | | | |

## A · 工程师独立首答

在查看模型建议前保存此表，记录工程师、完成时间和资料版本。允许写“无法判断”。

| 案例编号 | 找到的证据及时间范围 | 缺少的证据 | 下一项检查 | 不同检查结果会如何改变判断 |
| --- | --- | --- | --- | --- |
| | | | | |

## B · 同一工程师查看 AI 后复答

保留 A 原稿，并记录调查 ID、模型、Prompt 版本、建议及引用。为每条影响决策的建议各写一行。若模型没有返回答案，记录请求结果，结束该例的模型可用性记录。

| 案例编号 / 建议 ID | AI 引用及核对结果 | 采纳、修改或拒绝的理由 | 新增或撤回的证据 | 复答的下一项检查及其区分作用 |
| --- | --- | --- | --- | --- |
| | | | | |

## C · 独立评审

先匿名呈现两份答案并调整顺序，让评审者分别评分，然后揭示 A、B 的对应关系，记录方向。比较时按含义匹配底稿中的关键证据，每项在每份答案内仅计一次。检查的区分作用应解释“结果支持哪种解释、削弱哪种解释”，并允许多种有依据的做法。

| 案例编号 | A 命中 / 遗漏的关键证据 ID | B 命中 / 遗漏的关键证据 ID | 下一项检查的区分作用改善、变差或持平及依据 | AI 带来的补充、误导或无变化 | 无依据建议被采纳 / 有用建议被误拒的 ID 与理由 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

汇总时列出总例数、模型未应答数、可配对评审数，以及证据充分与不足两组的结果。分别报告两类误判的条数及被评建议总数。材料不足以判定的建议单列。保留分歧和可能的顺序效应；同一工程师的第二次作答还受到再次阅读资料的影响。
